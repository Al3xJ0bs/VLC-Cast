# CHANGELOG — VLC Cast

История версий, коротко: что изменилось в каждой версии. Подробности
исследования прямого каста — в
`research/direct-cast-research-2026-11-10.md`.

## v0.9.3.5 (2026-11-18)

- Встроенное обновление только скачивало APK, но установку само не
  начинало. Причина: в 0.9.3.1 краш запуска чинили флагом
  `RECEIVER_NOT_EXPORTED` — и он же молча отрезал доставку системного
  `ACTION_DOWNLOAD_COMPLETE` (DownloadManager — другой UID; по
  документации Android системный broadcast требует `RECEIVER_EXPORTED`).
  Теперь: activity-receiver с `RECEIVER_EXPORTED`, плюс
  manifest-receiver `UpdateDownloadReceiver` (живёт, даже если
  приложение убито mid-download), плюс re-check при запуске. Из фона
  установка доставляется уведомлением с PendingIntent (прямой
  `startActivity` из фона режется ограничением Android 10+). Если
  разрешения на установку нет, а APK уже скачан — файл запоминается
  как «ждёт установки»: после разрешения установка начинается без
  повторного скачивания.

## v0.9.3.4 (2026-11-18)

- Пробуждение спящего Apple TV: раньше был только Companion `turn_on`,
  а спящий ТВ не слушает ни 7000, ни 49153 — команду доставить некому.
  Теперь первым шагом Wake-on-LAN: magic packet (6×0xFF + MAC×16,
  102 байта, 3 раунда) на broadcast подсети ТВ и на 255.255.255.255:9.
  MAC берётся из `/proc/net/arp`, когда ТВ доступен, и кэшируется;
  без MAC — честный статус «включите ТВ пультом один раз», флоу не
  прерывается. Порядок: probe → WoL → ожидание до 30 с → turn_on →
  mDNS fallback.
- Кнопка «Поделиться логом» убрана с главного экрана; осталась только
  в уведомлении «Видео не найдено» и на экране краша.

## v0.9.3.3 (2026-11-18)

- Instagram кастился, но только звук: рилс отдаёт звук и видео
  раздельными файлами, и проба зеркал выбирала аудио-файл по
  латентности. Теперь кандидаты с аудио-тегом в `efg` (`vencode_tag`
  содержит `audio`) исключаются из видео-кандидатов, а URL с
  `bytestart`/`byteend` (диапазоны байт DASH-сегмента) понижаются
  в выборе.
- Шаринг видеофайла из Telegram — «Не удалось открыть файл»: копия
  в сервисе падала с `FileNotFoundException: ENOENT`. Копия переехала
  в саму activity шаринга (полупрозрачный экран с прогрессом,
  activity живёт до конца копии); сервисная копия осталась как
  fallback. В лог пишутся scheme/authority/`getType` URI и класс
  ошибки.
- Параллельные запуски сериализованы: раньше несколько запусков
  в одну секунду гоняли параллельные Companion-коннекты и давали
  `EOFException`/`Connection reset`. Теперь один коннект за раз.

## v0.9.3.2 (2026-11-18)

- Хотфикс краша при шаринге видеофайла из Telegram: NoDisplay-activity
  обязана вызвать `finish()` в `onCreate`, а редизайн 0.9.3 копировал
  файл в фоновом потоке activity с отложенным `finish()`. Копия
  переехала в `CastService`: activity только форвардит URI и сразу
  `finish()`, сервис копирует с таймаутом 60 с.
- Instagram: видео находится, но VLC не загружает. CDN Instagram
  (`instagram.com` / `cdninstagram.com` / `fbcdn.net`) добавлены
  в локальный прокси — поток идёт с Referer страницы поста,
  десктопным UA и куками WebView. Точный итоговый URL пишется
  полностью в лог.
- Чистка главного экрана: самопроверка и проверка обновлений —
  автоматически при запуске, в фоне; кнопки и поле URL источника
  обновлений убраны (источник всегда вшитый); экспорт/импорт
  спаривания удалены полностью; поле ключа OpenSubtitles убрано
  с главного экрана (сохранённый ключ продолжает работать, новый
  ввести в UI нельзя).

## v0.9.3.1 (2026-11-18)

- Хотфикс краша при запуске 0.9.3: `AppUpdater` регистрировал
  `BroadcastReceiver` двухаргументным `registerReceiver` — на
  Android 13+ с targetSdk 33+ это обязательный `SecurityException`.
  Исправлено на трёхаргументный вызов с `RECEIVER_NOT_EXPORTED`.
- Заодно: захардкоженная версия в `CrashLog` (`0.1.1-cast2`)
  заменена на актуальную — крэш-экран теперь пишет верную версию.

## v0.9.3 (2026-11-18)

- Самообновление внутри приложения: кнопка «Скачать и установить» —
  DownloadManager с прогрессом, затем автоматический промпт установки.
  Подпись проверяет сам Android при установке поверх.
- DASH из раздельных дорожек: прокси синтезирует локальный `.mpd`
  (пока только YouTube adaptive: видео-only + аудио-only).
- 60fps как tie-break при равном качестве; проба скорости зеркал
  (первый байт, дедлайн 2,5 с); проверка установки VLC на ТВ до
  запуска (честная ошибка вместо тишины); куки + вход через fallback
  браузер; самопроверка при первом запуске; карточка «Что нового»;
  JSON-LD VideoObject; oEmbed; десктопный UA как третий рескан;
  lazy-iframe активация; бэкап спаривания (экспорт/импорт, удалён
  в 0.9.3.2).
- Хотфиксы 0.9.2: Telegram-файл — сервис теперь стартует синхронно
  в `onCreate` до копии (раньше старт откладывался и умирал молча);
  Instagram «Видео не найдено» — прямой HTTP-fetch HTML с десктопным
  UA, когда WebView-скан пуст (страница входа без `og:video`).

## v0.9.2 (2026-11-18)

- Каст музыки: та же механика, что у видео. Прямые ссылки
  (mp3/aac/flac/ogg/m4a/wav/opus, HLS-аудио), SoundCloud, YouTube
  Music, интернет-радио (`.pls`/`.m3u`), Bandcamp, локальные
  аудиофайлы с автоудалением копии. Видео в приоритете: аудио
  кастится, только если видео нет. Spotify и Apple Music — вне
  скопа (DRM), при шаринге — честная ошибка.
- Источник обновлений по умолчанию: публичный репозиторий,
  `latest.json` в корне ветки `main`; проверка различает 404,
  ошибку сети и мусор в JSON.
- Исправлены два срочных бага 0.9.1: (1) шаринг видеофайла из
  Telegram — «Не удалось открыть файл»: grant на чтение URI жил
  только пока жива activity, а она закрывалась сразу после старта
  сервиса; теперь файл копируется самой activity во временный
  каталог и сервису передаётся путь. (2) Каст не шёл ниоткуда:
  TV pre-check без fallback на mDNS, очередь-ловушка после
  успешного запуска с неизвестной длительностью, зависшее
  состояние при ошибке запуска.

## v0.9.1 (2026-11-18)

16 фич: проверка обновлений; блок статуса на экране-инструкции;
запоминание озвучки; resume (позиция по таймеру, HLS через
прокси); плейлисты YouTube; название видео в уведомлении;
проверка ТВ заранее (TCP-проба, пробуждение, до 30 с); очередь
шарингов; запоминание выбора субтитров; пробуждение ТВ через
Companion `turn_on`; предзагрузка следующей серии; постер
в уведомлении; субтитры из OpenSubtitles (нужен бесплатный
consumer API key); шаринг видеофайлов (Telegram, галерея);
Instagram (`og:video` из страницы); Twitch и Kick — master-first.

## v0.9.0 (2026-11-18)

- Авто-ретрай: pre-flight проверка каждого кандидата (Range GET;
  для HLS — master, вариант и первый сегмент); порядок попыток
  как у автовыбора, максимум 3; все исчерпаны — честное
  «Видео недоступно».
- Авто-следующая серия: таймер по длительности (YouTube
  `lengthSeconds`, сумма `#EXTINF` у HLS, `mvhd` у mp4,
  `mediaPresentationDuration` у DASH) + 20 с на старт VLC;
  список серий — по ссылке «Следующая серия», номерному шаблону
  или `?ep=`; уведомление с кнопкой «Отменить».
- Кнопка «Поделиться логом» в уведомлении «Видео не найдено»
  (свой FileProvider, только `aircast.log`).
- Субтитры двумя путями сразу: синтетический HLS-master с
  группой SUBTITLES через прокси (SRT/ASS→VTT на лету) и
  параметр `sub=` в vlc-x-callback-url.

## v0.8.1 (2026-11-18)

Generic-парсинг плееров, без привязки к сайтам: нормализация
HTML в SCAN_JS (`\/`, `\u002F`, `&amp;`); процентно-закодированные
URL; сплиттер списков Playerjs; резолв относительных URL;
новые data-атрибуты (`data-stream`, `data-source`, `data-playlist`,
`data-mp4`, `data-m3u8`, `data-video-url`, `data-hls-url`,
`data-file-url`); JWPlayer feed; новые селекторы play.
Честно не поддерживается: blob/MSE, DRM (Widevine), Plyr+Vimeo
без Vimeo API.

## v0.8.0 (2026-11-18)

Универсальная поддержка плееров: YouTube через InnerTube
(VISIONOS — HLS-манифест без cipher; ANDROID — только itag 18);
JS-скан v2 (`.m3u8`/`.mp4`/`.mpd` в скриптах и конфигах плееров,
VK files, CVH `hlsUrl`, метаданные OK.ru); авто-play v2;
master-плейлист первым; локальный прокси (Referer + куки
WebView, только для хостов, которым он нужен). Честно не
поддерживается: Alloha статически, Kodik `/ftor`, HDRezka
AJAX replay, расшифровка `signatureCipher`.

## v0.7.0 (2026-11-18)

Шаринг в фоне: `ShareReceiverActivity` (без UI) извлекает ссылку
и стартует `CastService` (foreground); пользователь остаётся
в браузере; уведомления «Отправляю видео…» → «Видео запущено ✓».
`CastEngine` — весь авто-флоу, отвязанный от Activity.
MainActivity по умолчанию — только экран-инструкция.

## v0.6.0 «VLC Cast» (2026-11-18)

Максимальная автоматизация: шаринг ссылки из Chrome → авто-детект
→ авто-запуск во VLC, ноль ручных шагов. Один экран вместо
мастера 1-2-3. Зеркало удалено полностью. Ручной ввод URL,
«Найти видео», «Тест. видео», «Открыть плеер на телефоне» —
удалены. Авто-выбор: HLS первым, затем mp4, затем большее
разрешение. Авто-открытие страницы плеера и авто-play при
iframe без видео. ТВ — запомненный, иначе авто-поиск mDNS
(один ТВ — сам, несколько — выбор один раз).

## v0.5.2 (2026-11-18)

- Исправлен невидимый браузер: WebView на шаге 2 измерялся
  в 0 px (корень без layout params → WRAP_CONTENT). Все экраны
  теперь MATCH_PARENT, у WebView minHeight 200dp.
- Прямой каст удалён целиком (`/play`, `/command`, PTP,
  AirPlayVideoClient, CommandFlow, HlsProxy): мёртв на tvOS 27.2.

## v0.5.0-vlc-test (2026-11-10)

Первый рабочий путь каста: VLC на ТВ через Companion
(`_launchApp` + `vlc-x-callback://x-callback-url/stream`).
OPACK по pyatv, Companion Pair-Setup (SRP) с PIN на экране ТВ,
Pair-Verify, сессионные ключи. Живой тест: MP4 и HLS играют
на ТВ.

## v0.4.0–v0.4.9 (2026-11-10) — зеркало экрана (удалено в v0.6.0)

- v0.4.8: доказана причина чёрного экрана — кадры шли в Annex-B
  вместо AVCC; добавлен конвертер `annexBToAvcc`. После фикса
  зеркало работает: картинка на ТВ.
- v0.4.7: TimeAnnounce (RTCP sync), запись потока в дамп ACD1
  + независимый верификатор.
- v0.4.6: чтение тела ответов SETUP/feedback, `skipRecord`,
  проверка ключа шифрования (совпал с doubletake байт в байт).
- v0.4.5: метки кадров в таймлайне ТВ, разбор SPS.
- v0.4.4: ключевые кадры — первый IDR терялся до старта стрима;
  сторож ключевых кадров.
- v0.4.3: PTS из другого домена часов, таймаут чтения data-канала.
- v0.4.0: зеркало экрана — MediaProjection → GLES-кроп →
  H.264 1920×1080 → AirPlay 2 (FairPlay SAP, ChaCha20-Poly1305).
- v0.4.9: геометрия кропа в пространстве буфера; поворот
  посреди сессии роняет приложение (один MediaProjection —
  один createVirtualDisplay, ограничение платформы).

## v0.3.0–v0.3.5 (2026-11-09/10) — прямой каст (мёртв)

Прямой каст через `/command` (`insertPlayQueueItem`): HTTP 400
во всех формах — минимальная, полная, с messageID, с
Start-Position в мс и в секундах, для mp4 и HLS. Закрыто как
мёртвое на tvOS 27.2.

## v0.2.0–v0.2.1 (2026-11-09)

Мастер 1-2-3, single-session guard, NTP-фикс, V1 fallback.
ТВ не загружал медиа через `/play` ни в одной форме.

## v0.1.3 (2026-11-09)

- Исправлен pair-verify M4 error 2: подпись M3 контроллера
  должна быть over `ourPublic + clientId + serverPublic`
  (было — порядок M2). Доказано перекрёстной проверкой с pyatv
  и строгим моком.
- Кандидаты — только настоящие видео-URL, не страницы плеера.

## v0.1.2 (2026-11-09)

Доказана причина вылета v0.1.0; починен JS-скан (parse error
на каждом запуске); плеер Alloha распознан наряду с Kodik;
`/server-info` 403 больше не затирает features; плейсхолдер
`blank.mp4` исключён из кандидатов.

## v0.1.1 (2026-11-09)

Вылет при запуске сделан видимым: CrashHandler в Application,
маркеры запуска с fsync, первый кадр до WebView, экран краша.
Причина вылета v0.1.0 на тот момент была неизвестна.
